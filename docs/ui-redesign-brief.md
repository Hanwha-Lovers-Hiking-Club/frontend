# UI 리디자인 문서

상태: 레퍼런스 수집 중
작성일: 2026-10-09

## 디자인 원칙

서비스가 추구하는 핵심 가치는 **심플함, 모던함, 생동감**이다.

### 심플함

- 화면마다 사용자가 지금 해야 할 행동 하나를 가장 먼저 보이게 한다.
- 장식용 카드, 불필요한 안내, 중복 버튼을 추가하지 않는다.
- 충분한 여백과 명확한 정보 계층으로 복잡한 기능도 쉽게 읽히게 한다.

### 모던함

- 공통 사이드바·검색 패널·상세 패널에 일관된 표면, 경계, 라운드 체계를 사용한다.
- 차분한 중립색을 바탕으로 하나의 절제된 강조색을 사용한다.
- 큰 제목, 읽기 쉬운 본문 폭, 정돈된 타이포그래피로 화면의 밀도를 조절한다.
- 유행성 강한 AI 그라디언트나 과도한 그림자보다 정보와 상호작용의 선명함을 우선한다.

### 생동감

- 생동감은 많은 장식이 아니라, 반응하는 인터페이스에서 만든다.
- 사이드바 축소, 상세 패널 열기, 버튼 호버·누름, 카드 포커스, 업로드 진행처럼 사용자의 행동과 상태 변화에 짧고 자연스러운 움직임을 준다.
- 챗봇 인사말의 변주, 업로드 단계의 스트리밍 메시지, 로딩 애니메이션은 서비스가 살아 있는 느낌을 주는 핵심 요소다.
- 움직임은 짧고 목적이 있어야 하며, 사용자가 멀미를 느끼거나 작업을 기다린다고 느끼게 하지 않는다.

### 구현 내구성 및 상태 검증

- 공통·인터랙티브 컴포넌트는 우연한 콘텐츠 크기나 flex 동작에 의존하지 않는다. 폭·최소/최대 폭·행 높이·아이콘 영역 등 정렬의 기준점을 명시적으로 정한다.
- 기본, 호버, 포커스, 선택, 로딩, 펼침/접힘, 반응형 상태에서도 같은 정렬 기준점과 여백을 유지한다. 상태 전환 때문에 요소가 밀리거나 겹치거나 너비가 한 번 더 줄어들면 안 된다.
- 요청한 부분만 수정하더라도 그 컴포넌트의 인접 요소와 모든 상태를 함께 확인한다. 특히 공통 레이아웃은 대표적인 데스크톱·모바일 폭에서 오버플로와 시각적 흔들림을 검증한다.
- 모션은 레이아웃 이동을 숨기기 위한 수단으로 쓰지 않는다. 구조와 크기를 먼저 안정시키고, 그 위에 자연스러운 색상·투명도·위치 전환을 더한다.

## 정보 구조 결정

- 대시보드 페이지는 제공하지 않는다.
- 첫 진입 경로(`/`)는 사이드바와 화면 제목에서 `챗봇`으로 표기한다.
- 챗봇은 별도의 대시보드가 아닌, 서비스의 실질적인 메인 페이지 역할을 한다.

## 1. 사이드바

### 디자인 방향

- 화면 왼쪽 끝에 붙은 고정 네비게이션이 아니라, 여백을 두고 놓인 독립 패널로 만든다.
- 패널은 적당한 모서리 반경을 사용해 둥글고 부드러운 인상을 준다.
- 바깥 배경과 사이드바를 구분하되, 무거운 그림자보다 얇은 경계와 은은한 표면 대비를 우선한다.

### 기본 상태

- 넓은 상태에서는 아이콘과 라벨을 함께 보여준다.
- 메뉴 항목은 세로 목록으로 배치한다.
- 현재 위치는 배경, 텍스트 색상 또는 작은 강조 요소로 분명하게 표시한다.
- 하단에는 도움말·설정·계정 등 보조 메뉴 영역을 분리할 수 있다.
- 도움말과 설정은 기능을 붙이기 전에도 버튼 형태와 접근성을 유지한다. 다만 일반 포인터 대신 기본 화살표 커서를 사용한다.

### 축소 상태

- 접을 때 완전히 사라지지 않는다.
- 패널의 폭만 줄이고 각 메뉴를 대표 아이콘으로 유지한다.
- 축소 상태에서도 패널의 배경, 라운드 형태, 활성 상태는 유지한다.
- 아이콘만 남을 때는 툴팁 또는 접근 가능한 라벨을 제공한다.
- 로고와 사용자 영역은 축소 상태에 맞는 아이콘/아바타 표현으로 대체한다.
- 축소 상태의 패널 폭과 로고 영역은 고정한다. 기본 로고는 검정 배경과 흰 아이콘을 유지하며, 마우스를 올렸을 때만 밝은 표면의 어두운 화살표로 페이드 전환된다. 클릭하면 사이드바가 다시 펼쳐진다.

### 레이아웃 계약

- 데스크톱 패널 폭은 넓은 상태 240px, 축소 상태 72px으로 고정한다. 패널 내부 여백은 12px으로 고정한다.
- 축소 상태의 아이콘 중심점은 패널 왼쪽에서 36px으로 고정한다. 로고와 계정 아바타는 48px 정렬 슬롯의 가운데를 사용하고, 메뉴·보조 메뉴는 같은 왼쪽 패딩과 20px 아이콘 크기로 이 중심을 맞춘다.
- 정렬 기준만 고정하고 실제 로고·아이콘·아바타의 표면 크기는 콘텐츠 허그 방식으로 둔다. 로고나 아이콘을 교체해도 공통 중심축은 유지한다.
- 챗봇·문서 업로드·지식카드·도움말·설정은 하나의 공통 행 구조를 사용한다. 아이콘 뒤 라벨 간격은 10px으로 통일하며, 보조 메뉴만 별도의 여백 보정을 하지 않는다.
- 펼침/축소 상태에 따라 정렬 슬롯, 좌우 패딩, `justify-content`, 요소 종류를 바꾸지 않는다. 패널 폭만 전환하고, 라벨은 투명도와 바깥 클리핑으로 처리한다.
- 로고는 하나의 공통 슬롯 안에 유지한다. 넓은 상태의 로고와 축소 상태의 펼치기 제어를 별도 요소로 교체하지 않는다.

### 동작

- 넓힘/축소 전환은 즉시 끊기지 않고 짧은 폭·투명도 전환으로 처리한다.
- 접히는 동안 아이콘·브랜드·하단 보조 요소의 왼쪽 정렬 기준점은 유지한다. 요소를 먼저 중앙 정렬한 뒤 패널을 줄이지 않고, 패널 자체가 요소 위로 접히는 인상을 만든다.
- 전환 중 본문 레이아웃이 밀리거나 가로 스크롤이 생기지 않아야 한다.
- 키보드 포커스와 현재 페이지 표시를 제공한다.
- 모든 실제 버튼과 클릭 요소에는 포인터 커서를 사용한다. 도움말·설정처럼 기능 대기 상태인 보조 버튼은 기본 화살표 커서를 사용한다.
- 모바일에서는 같은 패널을 유지할지, 별도 드로어로 바꿀지 전체 정보 구조 확정 후 결정한다.

### 레퍼런스에서 확인한 요소

- 패널형 외곽 구조
- 넓은 상태의 아이콘+텍스트 메뉴
- 축소 상태의 아이콘 전용 메뉴
- 상단 브랜드/워크스페이스 영역
- 하단 보조 메뉴 및 계정 영역
- 선택된 메뉴를 구분하는 배경 또는 강조 표시

### 이번 문서에서 아직 정하지 않은 것

- 패널의 정확한 폭과 축소 폭
- 라운드 값과 외부 여백
- 색상 모드와 강조 색상
- 아이콘 세트
- 모바일 동작
- 사이드바가 본문 위에 겹치는지, 본문을 밀어내는지

## 2. 챗봇 시작 화면

### 목적

- 사용자가 대화를 시작하기 전에 서비스가 무엇을 도와주는지 빠르게 이해하게 한다.
- 첫 질문을 입력하는 순간까지의 망설임을 줄인다.

### 화면 구성

1. 중앙에 큰 인사말형 타이틀을 둔다.
2. 타이틀 바로 아래에 채팅 입력창을 둔다.
3. 입력창 아래에는 자주 쓰는 질문을 빠른 시작 항목으로 노출한다.
4. 그 아래에 별도의 카드 그리드·추천 섹션은 두지 않는다.

### 타이틀

- 큰 크기와 충분한 여백으로 첫 화면의 중심 역할을 한다.
- 단일 고정 문구가 아니라 여러 인사말 세트를 준비한다.
- 방문하거나 새 대화를 시작할 때 세트 중 하나를 선택해 보여준다.
- 문구는 친근하되 서비스의 역할을 설명하는 방향으로 유지한다.
- 실제 문구와 교체 조건은 나중에 정한다.

### 채팅 입력창

- 인사말 아래에 배치해 첫 행동이 명확하도록 한다.
- 짧은 안내 문구와 전송 동작을 포함한다.
- 화면의 주인공이므로 주변 요소보다 시각적 우선순위를 높인다.

### 빠른 시작 질문

- 입력창 바로 아래에 버튼 또는 짧은 칩 형태로 둔다.
- 클릭하면 해당 질문이 입력되거나 즉시 전송되는 방식은 추후 결정한다.
- 항목의 주제·개수·문구는 실제 사용 시나리오를 정한 후 확정한다.

### 제외할 요소

- 레퍼런스 하단에 있는 카드형 그리드/기능 소개 섹션은 넣지 않는다.
- 첫 진입 화면은 콘텐츠를 많이 보여주는 대시보드가 아니라, 대화 시작에 집중한 단순한 화면으로 유지한다.

### 상태 및 동작

- 인사말 교체는 새로고침마다 무작위로 바뀌어도 되지만, 같은 세션에서 지나치게 자주 바뀌지는 않게 한다.
- 빠른 질문과 입력창은 키보드로도 접근·실행할 수 있어야 한다.
- 모바일에서는 큰 타이틀과 입력창이 첫 화면 안에 자연스럽게 들어오도록 세로 여백을 조절한다.

## 3. 챗봇 대화 화면

### 구조

- 데스크톱에서는 대화 영역이 화면의 전체 폭을 사용하지 않는다.
- 왼쪽의 공통 사이드바 다음에 대화 본문을 두고, 오른쪽에는 보조 패널 전용 폭을 확보한다.
- 대화 본문은 읽기 편한 폭을 유지하고, 메시지가 넓은 화면에서 과도하게 길어지지 않게 한다.
- 오른쪽 보조 패널은 대화와 동등한 페이지 구성 요소이며, 단순 팝업이나 모달로 대체하지 않는다.

### 대화 본문

- 대화 흐름과 입력창에 집중할 수 있는 중앙 작업 영역이다.
- 입력창은 대화 하단에서 쉽게 접근할 수 있게 유지한다.
- 대화가 길어져도 입력창과 최신 메시지의 관계가 자연스럽게 유지되어야 한다.
- 답변 내 코드, 목록, 링크처럼 길이가 다양한 콘텐츠가 본문 폭 안에서 읽기 좋게 표시되어야 한다.

### 오른쪽 보조 패널

- AI 답변을 보완하는 정보를 보여주는 전용 영역이다.
- 초기 후보 용도는 출처, 연결된 지식 카드, 관련 문서, 후속 추천이다.
- 실제 탭 구성·노출 순서·기본 콘텐츠는 나중에 확정한다.
- 보조 정보가 없는 경우에는 비어 있는 넓은 영역으로 방치하지 않고, 짧은 안내 또는 관련 정보를 준비하는 상태로 보여준다.
- 사용자가 필요할 때만 집중해서 볼 수 있도록 대화 영역보다 낮은 시각 우선순위를 둔다.

### 반응형 규칙

- 넓은 화면에서는 대화 본문과 보조 패널을 나란히 배치한다.
- 공간이 부족해지면 보조 패널을 접거나, 버튼으로 여는 슬라이드 패널로 전환한다.
- 모바일에서는 대화 본문을 우선하며 보조 패널은 별도 화면 또는 하단 시트 형태로 연다.

### 상태 및 접근성

- 답변 생성 중에는 본문에 진행 상태를, 보조 패널에는 출처·카드 분석 중 상태를 각각 표시할 수 있다.
- 보조 패널의 열기·닫기와 탭 전환은 키보드로 조작할 수 있어야 한다.
- 패널을 열거나 닫아도 입력 중인 메시지와 대화 스크롤 위치가 사라지지 않아야 한다.

### 이번 단계에서 제외하는 결정

- 보조 패널의 정확한 데이터 종류와 탭 이름
- 패널의 기본 열림 여부와 정확한 폭
- 출처·지식 카드의 상세 디자인

## 4. 지식카드 목록 화면

### 목적

- 축적된 지식을 검색하고, 조건으로 좁힌 뒤, 카드 단위로 빠르게 훑을 수 있게 한다.
- 사용자는 카드의 핵심 내용과 출처 단서를 목록에서 확인하고 상세 화면으로 이동한다.

### 상단 검색·필터 패널

- 페이지 상단에 검색과 필터를 하나의 독립 패널로 둔다.
- 이 패널은 공통 사이드바와 같은 언어를 사용한다: 바깥 여백, 부드러운 라운드, 정돈된 경계와 표면.
- 검색 입력창을 가장 먼저 배치하고, 그 아래 또는 옆에 필터·정렬·초기화 동작을 둔다.
- 초기 필터 후보는 카드 유형, 태그, 출처 문서, 프로젝트, 작성/갱신일이다. 실제 필드가 확정되면 조정한다.
- 현재 적용된 필터는 제거 가능한 칩으로 표시한다.
- 결과 수와 정렬 기준을 검색·필터와 가깝게 보여준다.

### 카드 그리드

- 검색·필터 패널 아래에 지식카드를 그리드로 배치한다.
- 큰 화면에서는 여러 열을 사용하되, 카드 안의 텍스트가 지나치게 좁아지지 않도록 열 수를 유동적으로 조절한다.
- 모든 카드를 같은 높이로 억지로 맞추기보다, 기본 정보의 배치 기준을 통일해 훑기 좋게 만든다.
- 카드 전체를 클릭하면 상세 화면으로 이동한다.
- 호버·포커스·선택 상태를 제공해 클릭 가능한 요소임을 분명히 한다.

### 임시 지식카드 스키마

아래 항목은 실제 스키마가 정해지기 전의 화면용 가안이다.

| 우선순위 | 항목 | 목록에서의 역할 |
|---|---|---|
| 필수 | 카드 유형 | 사례, 기술, 교훈 등 카드의 성격을 빠르게 구분 |
| 필수 | 제목 | 카드의 핵심 주제 |
| 필수 | 요약 | 제목만으로 부족한 맥락을 2~3줄로 보완 |
| 필수 | 태그 | 검색·필터와 주제 파악에 사용 |
| 권장 | 출처 | 연결된 문서명 또는 출처 수 |
| 권장 | 갱신일 | 정보의 최신성 판단 |
| 선택 | 프로젝트/작성자 | 데이터 규모와 소유 정보가 필요할 때 사용 |

### 페이지네이션

- 목록 하단에 명확한 페이지네이션을 둔다.
- 현재 페이지, 이전·다음 이동, 전체 결과 맥락을 제공한다.
- 무한 스크롤은 이번 범위에서 제외한다. 필요해지면 별도 작업으로 추가한다.
- 페이지 이동 후 사용자가 현재 결과 위치를 잃지 않도록 목록 상단과 초점 처리를 고려한다.

### 상태

- 로딩: 카드 형태를 따라가는 스켈레톤과 검색·필터 패널의 준비 상태를 표시한다.
- 검색 결과 없음: 적용된 조건을 보여주고 필터 초기화 동작을 제공한다.
- 오류: 목록을 불러오지 못한 이유와 다시 시도 동작을 인라인으로 표시한다.
- 모바일: 검색·필터를 세로로 정리하고, 카드 그리드는 한 열 또는 충분한 폭의 두 열로 전환한다.

### 이번 단계에서 제외하는 결정

- 실제 카드 유형 및 스키마
- 카드별 상세 통계·점수 노출 여부
- 정확한 필터 항목과 정렬 기준

## 5. 지식카드 상세 패널

### 열기 방식

- 목록에서 지식카드를 선택하면 별도 상세 페이지로 이동하지 않고, 화면 오른쪽에서 상세 패널이 슬라이드되어 열린다.
- 패널이 열릴 때 배경 전체에 딤을 적용해 현재 선택한 카드에 시선을 모은다.
- 카드 목록은 패널 뒤에 그대로 남아 있어, 닫은 뒤 검색·필터·페이지 상태를 유지한다.

### 패널 콘텐츠

- 상단: 카드 유형, 제목, 닫기 버튼
- 본문: 요약, 상세 지식 내용, 태그, 핵심 메타데이터
- 출처: 원본 문서명과 원본 문서를 열 수 있는 링크
- 실제 스키마가 확정되면 상세 필드를 조정한다. 현재는 목록의 임시 스키마를 확장하는 방식으로 구현한다.
- 내용이 길어질 수 있으므로 패널 내부만 독립적으로 스크롤한다.

### 닫기 동작

- 닫기 버튼을 제공한다.
- 패널 바깥의 딤 영역을 클릭하면 패널이 닫힌다.
- `Esc` 키로도 닫힌다.
- 닫힌 뒤에는 사용자가 선택했던 카드에 포커스를 돌려준다.

### 인터랙션 및 접근성

- 열고 닫을 때 짧고 부드러운 가로 이동·투명도 전환을 적용한다.
- 패널이 열린 동안 키보드 포커스는 패널 내부에서 순환한다.
- 배경 콘텐츠는 보이지는 않지만 현재 대화/목록 상태를 유지하며, 패널이 닫힐 때 즉시 원래 상태로 돌아온다.
- 패널의 제목을 접근 가능한 대화상자 이름으로 사용한다.

### 반응형 규칙

- 데스크톱에서는 오른쪽에서 열리는 고정 폭 패널을 사용한다.
- 좁은 화면에서는 패널 폭을 넓히고, 모바일에서는 화면을 거의 채우는 슬라이드 패널로 전환한다.

### 이번 단계에서 제외하는 결정

- 패널의 정확한 폭
- 상세 내용의 최종 데이터 스키마
- 원본 문서 링크의 미리보기·다운로드 정책

## 6. 문서 업로드

### 범위

- MVP에서는 파일 선택 방식만 제공한다.
- 드래그 앤 드롭은 이번 범위에서 제외하고, 이후 개선 작업으로 추가한다.
- 화면은 사이드바와 콘텐츠 영역을 유지하되, 콘텐츠 자체는 단순한 상태 전환 중심으로 구성한다.

### 구현 구조 계약

- 업로드 워크스페이스는 상태 전환, 선택 파일 데이터, 서버 진행 이벤트만 관리한다. 초기 선택·문서 확인·처리 진행·완료는 각각 독립 화면 컴포넌트로 둔다.
- 지원 파일 형식, 파일 식별 규칙, 파일 유형 추출은 하나의 공통 모듈에서 관리한다. 선택 화면과 문서 확인 화면이 서로 다른 지원 형식을 표시하면 안 된다.
- 파일 선택, 선택 파일 목록, 처리 진행, 완료 화면은 하나의 명시적인 상태 흐름으로 구분한다. 각 상태는 다른 상태의 레이아웃 조건에 의존하지 않는다.
- 파일 카드 목록은 `flex-wrap`으로 배치한다. 화면 폭에 따라 1·2·3·4개가 한 줄을 균등하게 채우며, 넓은 데스크톱에서는 4개 열을 사용한다.
- 카드의 계산된 `flex-basis`는 축소하지 않고, 카드와 내부 텍스트 영역에는 `min-width: 0`을 둔다. 긴 파일명·이미지 비율이 행의 폭 계산이나 썸네일 슬롯 크기를 바꾸면 안 된다.
- 선택 확인 헤더의 동작 버튼은 모든 화면 폭에서 우측 끝을 기준으로 정렬한다. 버튼이 다음 줄로 넘어가도 왼쪽 또는 중간에 남지 않는다.
- 파일 카드의 아이콘, 제거 동작, 파일명, 타입·용량 메타데이터는 각각 독립된 영역을 사용한다. 아이콘·색상·메타데이터가 바뀌어도 제목과 제거 버튼의 정렬 기준은 유지한다.
- 파일 카드의 중앙 영역은 문서 첫 페이지 썸네일 전용 슬롯이다. DOCX·XLSX·PPTX는 먼저 `docProps/thumbnail.jpeg`·`.jpg`·`.png`의 내장 Office 썸네일을 사용한다. DOCX와 XLSX에 내장 이미지가 없을 때만 각각 첫 물리 페이지 높이로 잘라낸 DOCX 렌더링 결과와 Excel 첫 시트 앞부분을 브라우저에서 렌더링한다. PPTX는 슬라이드를 다시 렌더링하지 않는다. 구형 XLS는 브라우저 썸네일 생성 대상이 아니며 빈 슬롯을 유지한다. 썸네일을 만들 수 없는 포맷·실패 상황에는 색상·문구·대체 그래픽을 넣지 않는다.
- 여러 PDF를 고르면 첫 페이지 썸네일은 순차 생성한다. 카드 목록을 한꺼번에 렌더링 작업으로 막지 않으며, 각 결과는 준비되는 즉시 해당 카드에 반영한다.
- 썸네일 생성 대상 카드는 이미지가 준비될 때까지 동일한 크기의 슬롯 안에 작은 스피너만 표시한다.
- 썸네일 원본 해상도와 JPEG 품질은 카드 슬롯보다 과도하게 높이지 않는다. 카드 표시 품질을 유지하는 범위에서 생성 시간·메모리·클라이언트 상태 크기를 줄인다.
- Excel 썸네일은 첫 시트의 앞쪽 6열과 8행을 고정 프레임으로 사용한다. 실제 데이터가 더 적으면 남은 셀은 비워두며, 카드·셀 크기는 문서마다 변하지 않는다.
- 썸네일 슬롯은 모든 파일 카드에서 같은 높이를 유지한다. 세로·가로 문서는 슬롯 안에서 비율을 보존해 표시하며, 빈 슬롯도 같은 공간을 차지한다.
- PPTX 내장 썸네일의 Object URL은 카드 제거, 업로드 초기화, 워크스페이스 이탈 시 즉시 해제한다.
- 실제 업로드 API와 스트리밍 단계가 연결되면, 화면 구조를 바꾸지 않고 진행 단계 데이터만 서버 이벤트로 교체한다.

### 1) 파일 선택 전

- 중앙에 페이지 제목, 짧은 안내, `파일 선택` 버튼을 둔다.
- `파일 선택`은 운영체제 파일 선택 창을 여는 동작이다.
- 버튼 이름은 이후의 `업로드 시작`과 구분해, 사용자가 파일을 고르는 단계와 실제 처리가 시작되는 단계를 혼동하지 않게 한다.
- 지원 형식·파일 수·용량 제한은 실제 업로드 정책이 정해지면 안내 문구에 추가한다.

### 2) 파일 선택 후

- 선택한 문서는 콘텐츠 영역에 그리드로 표시한다.
- 각 문서 카드에는 파일명과 식별에 필요한 최소 정보, 제거 버튼을 둔다.
- 우측 상단에는 실제 전송과 분석을 시작하는 `업로드 시작` 버튼을 둔다.
- 파일이 하나도 없으면 `업로드 시작` 버튼은 비활성화한다.
- 선택한 파일을 모두 제거하면 첫 상태로 돌아간다.

### 3) 업로드·분석 진행 중

- `업로드 시작`을 누르면 중앙 진행 화면으로 전환한다.
- 중앙에는 추후 로딩 애니메이션 라이브러리를 삽입할 수 있는 고정 영역을 확보한다.
- 현재 로딩 애니메이션 영역에는 VoiceOrbs의 Particles Orb를 사용한다. 실제 서버 처리 흐름이 연결되면 처리 상태별 시나리오에 맞춰 Orb 상태를 전환한다.
- 현재 프로토타입의 6단계 Orb 시나리오는 순서대로 `idle/turbo` → `listening/slow` → `thinking/turbo` → `speaking/slow` → `connecting/slow` → `idle/turbo`이다. 마지막 단계만 보라색 계열로 색상을 전환하며, 각 값은 처리 단계 데이터에서 한 곳으로 관리한다.
- 진행 화면은 전체 진행률·애니메이션 영역과 단계 큐를 분리해 넓은 화면에서는 두 열로 배치한다. 좁은 화면에서는 전체 진행률 영역이 먼저 나오고 단계 큐가 뒤따른다.
- 로딩 애니메이션 아래에 전체 진행률을 보여주는 프로그레스 바를 둔다.
- 그 아래에는 서버에서 스트리밍으로 받는 단계별 진행 메시지를 순서대로 표시한다. 전체 체크리스트를 한꺼번에 노출하지 않고, 현재 단계와 다음 두 단계만 보이는 3개 항목 큐를 사용한다.
- 단계가 갱신되면 기존 큐는 위로 빠지고 다음 항목은 아래에서 들어온다. 완료 여부 아이콘 대신 현재 항목의 표면과 텍스트 대비로 진행 위치를 알린다.
- 예: 파일 업로드, 문서 읽기, 내용 추출, 지식카드 생성. 실제 단계 명칭은 백엔드 처리 흐름에 맞춰 확정한다.
- 진행 중에는 중복 업로드와 페이지 이탈로 인한 혼란을 방지할 상태 처리가 필요하다. 취소 가능 여부는 기능 범위 확정 후 결정한다.

### 4) 완료 후

- 완료 메시지와 처리 결과의 간단한 요약을 중앙에 표시한다.
- 주요 버튼은 `지식카드 보러가기`로, 지식카드 목록 화면으로 라우팅한다.
- 보조 버튼은 `새 문서 업로드`로, 선택 전 첫 상태로 돌아간다.

### 오류 상태

- 파일 선택·업로드·분석 중 실패하면 실패한 파일 또는 단계와 다시 시도 방법을 인라인으로 보여준다.
- 이미 선택된 파일과 진행 로그는 가능한 한 유지해 처음부터 다시 고르지 않도록 한다.

### 반응형 규칙

- 데스크톱에서는 파일 카드 그리드와 우측 상단 `업로드 시작` 동작을 유지한다.
- 모바일에서는 버튼을 제목 아래 또는 화면 하단의 쉽게 닿는 위치로 옮기고, 파일 카드 그리드를 한 열로 전환한다.

### 이번 단계에서 제외하는 결정

- 드래그 앤 드롭
- 파일 형식·개수·용량 제한
- 업로드 취소·재개 정책
- 실제 로딩 애니메이션 라이브러리와 모션 디자인
